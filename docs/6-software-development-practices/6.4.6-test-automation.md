# Automated Testing

Automated testing in CI helps maintain code quality by running the suite on every commit;  
all the correctness, quality, and security tests in the world buy nothing if they don't run.

Enforcing that on each commit not only keeps detectably bad code out of `main`,  
it surfaces the failure while the change is still fresh in the author's head.

With GitHub Actions, we can embed automated testing *workflows* within our GitHub repositories  
that trigger on branch pushes and PRs. Marking a workflow's status check as required  
in branch protection rules turns those workflow runs into PR merge gates.

?> If you want to test the creation or alteration of a GitHub workflow before committing it, you can use a tool called [ACT](https://github.com/nektos/act)

## Exercise 1 - writing tests

Create unit tests for the following functions:
```go
package arithmetic

func Add(a, b int) int { return a + b }
func Mul(a, b int) int {
  var c int = 0
  for range b { c += a }
  return c
}
```
Verify they work locally with `go test`.  
Discuss with fellow apprentices whether or not your unit tests make sense for these functions and would flag potential issues.

*If you didn't already make a GitHub repo for this exercise,*  
*make one now, then commit and push your local changes up.*

## Exercise 2 - automated testing

Create a new GitHub actions workflow called `unit-test`.  
The workflow should run your unit tests whenever code changes are pushed to ***any*** branch.  

Ask yourself: "What needs to happen for this workflow to run `go test` on my repo?"  

Verify by committing and pushing changes to GitHub,  
then checking the repo's "Actions" tab on GitHub to see that `unit-test` ran successfully.

Compare approaches with fellow apprentices.

*Recall that you can test workflow runs locally using the [ACT](https://github.com/nektos/act) tool*

## Exercise 3 - status badges

Add a status badge to the top of the repo's `README.md` file for `unit-test` workflow,  
showing the latest `passing` or `failing` status,  
e.g.

![Static Badge](https://img.shields.io/badge/unit--test-passing-brightgreen) or
![Static Badge](https://img.shields.io/badge/unit--test-failing-red)  

depending on the latest status.

Verify both statuses are shown by committing a change that fails the unit tests,  
then a change that passes the unit tests.
